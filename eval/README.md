# 오프라인 평가 코드와 공개 범위

이 디렉터리는 테스트에 필요한 정적 시나리오, 정답 기준, 출처 매핑만 포함합니다. 평가 실행의 원시 응답·채점 원장·환경 스냅샷·예산 상태·동결된 로컬 설정은 공개하지 않고 로컬에 보존합니다. 따라서 이 저장소는 전체 실행 기록을 재배포하는 재현 패키지가 아닙니다.

먼저 [결정 기록과 면접 가이드](../docs/EVAL-INTERVIEW-GUIDE-2026-11-17.md)를 읽으면 최종 기준과 초기 프로토콜의 차이를 확인할 수 있습니다.

## 결과 해석

2026-11-17 기준 35문항 통제 시험의 자동 주 점수는 간소화 하네스 61.8점, Pi 53.6점입니다. 반복별 우열, 미해결 채점, 표본 대표성의 한계 때문에 최종 순위나 확정 정확도로 해석할 수 없습니다. 신뢰할 만한 최종 순위라는 목표는 미달 상태이며 추가 평가는 중단되어 있습니다.

- [전체 결과와 검증 범위](../docs/EVAL-V5-VERIFIED-RESULTS-2026-11-17.md)
- [신뢰성 결론](../docs/EVAL-V5-RELIABILITY-CONCLUSION-2026-11-17.md)
- [별도 장애 재현 시험](../docs/EVAL-V5-CANONICAL-RESULTS-2026-11-17.md)
- [평가 프로토콜](../docs/EVAL-V5-PROTOCOL.md)

결과 문서의 원시 기록 경로는 로컬 보존 자료를 가리킬 수 있습니다. 공개 저장소만으로 해당 실행의 점수를 독립 재집계할 수 있다는 주장은 하지 않습니다.

## 추가 출력 한도 진단

[잘린 33개 요청의 별도 재시험](../docs/EVAL-JUDGE-TOKEN-DIAGNOSTIC-2026-11-17.md)에서는 진단용 출력 한도를 16,384로 올려 33개 모두 정상 완료·로컬 검증 통과를 확인했습니다. 이는 판정 정확도 검증이나 전체 점수 갱신이 아닙니다. 공통 채점기의 기본 한도 4,096은 그대로이며, 진단 실행에는 비공개 로컬 원본과 예산 등록부가 필요합니다. 진단 원시 자료도 공개하지 않습니다.

## 공개 테스트 입력

- `v4/dataset.json`: 35문항 통제 데이터셋의 원본.
- `v5/legacy-migration/`: 같은 시나리오의 구조화 응답 계약과 수치 측정 기준.
- `v5/dataset.json`, `gold*.json`, `provenance.json`: 격리 환경에서 재현한 PostgreSQL 장애 원리 2종의 8개 관측 조건과 출처·정답 기준.
- `v5/canonical-core/`: 정답을 드러내지 않는 공통 질문 필드와 데이터 변환 체크섬.

실제 운영 장애의 대표 표본과 동일하지 않습니다. 합성·수동 구성 사례, 장애 원리를 재현한 사례, 관측 제한 조건을 구분해 해석해야 합니다.

## 로컬 검증

Python 3.10+에서 `PyYAML`과 `promql-parser`를 설치한 뒤 저장소 루트에서 실행합니다.

```bash
python3 -m unittest discover -s scripts/tests -v
```

과거 실행 아카이브의 체크섬·수집 결과를 확인하는 두 테스트 클래스는 해당 로컬 아카이브가 없으면 명시적으로 건너뜁니다. 일반 채점·예산·검수 로직 테스트는 임시 합성 입력을 사용하며 API나 실제 예산 원장을 필요로 하지 않습니다.

Java 테스트 중 `@SpringBootTest`, `eval`/`drill` 태그 및 명시적 환경 변수로 활성화하는 테스트는 서버·모델 연결이 필요할 수 있습니다. 오프라인 확인은 일반 단위 테스트만 선택해서 실행합니다. 실제 유료 채점은 별도의 예산 등록과 입력 동결 검사를 요구하며 이 문서의 테스트 명령으로 실행되지 않습니다.

공개 실행 코드의 기본 모델 주소는 localhost입니다. 원래 실험 환경의 주소와 서버 전용 Compose 변경은 포함하지 않습니다. 새 실행에는 환경에 맞는 endpoint와 예산 설정이 필요합니다.
