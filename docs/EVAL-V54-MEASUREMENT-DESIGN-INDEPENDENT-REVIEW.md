Removing the model-generated aggregate pass label is principled. Restricting validated unsupported-claim assessment to structurally conforming answers is also defensible before broad collection, but it changes measurement scope and must be reported as such. Neither change makes the failed v53 gate pass retroactively.

Post-freeze inspection found 60 completed v53 judgments with eight failures. Three were consistent unsupported-label mismatches for Boolean false supplied where numeric exit code zero was requested. Five were aggregate-pass inconsistencies on quoted-number or malformed-final-JSON controls. In the latter cases, atomic findings correctly described grounded substantive content while the model set pass false because the requested structure failed. The existing deterministic composition would already reject strict structured pass. Asking the model to repeat a conjunction therefore introduced an unnecessary second interpretation of pass.

The minimum sound aggregate change is to remove that redundant output and compute strict pass from validated atomic findings, deterministic numeric checks, requested output conformity, unsupported-claim assessment and runner status. This loses no independent information when the aggregate is defined by those constituents. Keep the original strict-pass meaning; do not accept malformed output merely because substantive prose is correct.

The proposed unsupported-claim restriction is different: it deliberately declines to certify that property for parse/schema-invalid answers. Such answers can still contain clear factual claims, including blatant fabricated prose. Consequently, UNASSESSED must never mean false, claim-free, harmless or semantically correct. A uniform observable scope rule is preferable to special-casing particular failed controls: assess unsupported claims only when the final answer object parses and every requested field conforms under the published type/null policy. Outside that domain, retain any raw model flag as an unvalidated diagnostic, with final `unsupported_claims: null` and an explicit unassessed status.

Approval of this narrower design requires these conditions before fresh controls or broad answers are evaluated:

- Strict pass requires an assessed, explicitly false unsupported flag, valid format/schema, all combined findings correct, and no runner error. Use explicit comparisons; `not None` must never count as a clean claim assessment.
- Stable unsupported-free credit requires both judgments to be assessed and to agree on no unsupported claims. Keep all answers in its denominator. Unassessed answers receive no clean credit.
- Report assessment coverage separately by arm, including parse failures, schema failures and unresolved judgments. A rate among conforming answers alone can be composition-biased when arms differ in formatting; it is not a general hallucination rate.
- Publish lower/upper sensitivity bounds treating unassessed and unresolved claim judgments adversely. Do not silently discard those answers or count them as confirmed unsupported claims either.
- Preserve requested-finding metrics: numerical fields still require deterministic code pass AND semantic satisfaction; other fields may retain grounded content credit despite a format failure. Name content correctness and strict structured pass separately.
- Keep invalid-format/type controls in the new validation set. Their expected assessment status and final nonpass must be validated, rather than dropping them from the gate. Include malformed answers containing explicit fabricated prose to demonstrate that the design records unassessed, never clean. Include conforming wrong numerical facts and entity/window errors that require unsupported claims true.
- Freeze the new definition and implementation before evaluating fresh independently authored controls. Preserve v53 code, all 60 results, labels, cost and failed status. State that failed controls informed a new development decision; do not portray the new scoped gate as proof that the original universal unsupported metric was reliable.

The existing broad family-macro field estimator need not change. The claim-assessment coverage change must still appear in reports and cannot be used to force a stable ordering. Canonical results and earlier independent reviews remain under their original definitions; they should not be silently rescored or relabeled with v54.

No broad answers existed or were inspected for this design review. Only frozen v53 diagnostic results and affected payloads were read after explicit authorization. No frozen code, expected labels or results were edited, and no model or paid calls were made. This is conditional approval of a prospective scoped measurement design, not approval of a future implementation or empirical gate.
