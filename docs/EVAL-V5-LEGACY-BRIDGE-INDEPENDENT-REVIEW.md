The independent tests and source review establish these narrower properties:

- Numeric fields require both deterministic correctness and semantic satisfaction. Semantic true cannot rescue a code failure; code true cannot rescue wrong quantity association or missing grounding. GB/GiB and rate/count traps remain nonpass. Unknown or ungradable numeric extraction is not silently converted into a correct number.
- Judge payload construction rejects arm, family, case, prior-score and raw-world top-level additions. Exact delivered observation records are preserved. Sidecar case IDs, original gold objects and hidden window metadata are not copied into the judge payload. Published measurement metadata is passed consistently; a different published interval is rejected against its binding schema. This is structural blinding, not a guarantee that answer style cannot suggest an arm.
- Parse validity, requested-schema conformity, semantic field credit and strict structured pass are separate. Missing categorical or secondary facts and wrong JSON types block strict structured pass while preserving independently supported semantic field credit. Unrelated NaN, duplicate JSON keys and nonfinal JSON prevent deterministic numeric credit. Unsupported claims and runner errors prevent strict structured pass.
- Empty answers receive deterministic unanswered/nonpass judgments with no paid call. Existing results prevent replay. Missing, duplicate, misplaced-ledger and disagreeing judgments remain unresolved, with full answer and field denominators retained. Agreement is defined over final combined fields, unsupported claims and strict pass; raw semantic disagreement remains a separate diagnostic. A numeric failure can therefore make two differing raw semantic judgments agree on the same final nonpass.
- The plan predeclares exactly two child ledgers, each covering 210 answers with at most one planned call per answer. The underlying API's 240-attempt cap is not extra authorized work: the scorer has only the 210-cell loop, no repair calls, retries or automatic shards. The shared registry accounts for both children and all other registered campaigns under the same $2 budget; an uncertain previous outcome blocks further calls. Tests verify cross-ledger accounting and the uncertain-outcome stop. The global budget lock and per-ledger ownership lock address different races.
- A plan is frozen before collection and the completed model archive must contain that plan hash. Current and snapshot dependencies are checked; mutation of either fails verification. The separate validator defaults to offline preparation, checks 20 distinct synthetic controls and exhaustive typed deterministic labels, and compares final pass, unsupported and every finding label. The independent tests deliberately inject wrong values, integer-for-boolean labels, missing labels and duplicate IDs to verify rejection before any paid call.
