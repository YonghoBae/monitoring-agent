# 실제 사례 기반 벡터 검색 재평가 — 2026-11-17

작은 합성셋에서 BM25가 우세했던 결과는 일반화할 수 없었다. 실제 Unix/Linux 기록으로 다시 측정하자 벡터 검색이 더 높았다. 다만 오래된 공개 평가셋과 모델의 공개 학습 자료가 겹친다는 문제를 발견하여, **최근 실제 질문 100개를 별도로 확보해 추가 측정**했다. 이 추가 시험에서도 벡터·혼합 검색은 BM25보다 높았지만 벡터와 혼합의 우열은 확정하지 않는다.

이 점수는 **관련 기록 검색 성능**이다. 에이전트 답변 정확도, 원인 진단 정확도, 해결 명령의 안전성, 자동 복구 성공률을 뜻하지 않는다. 운영 검색 방식을 바꾸거나 배포하지 않았다. 기존 vector-v1도 그대로 보존했다.

## 1. 순수 합성 대신 어떤 근거를 사용했나

| 평가 | 문서 후보 | 질문 | 정답 관계 | 근거 |
|---|---:|---:|---:|---|
| 기존 vector-v1 | 40 | 정답 있음 60, 없음 8 | 작성한 합성 정답 | 공식 매뉴얼·공개 이슈를 참고한 진단 fixture |
| 역사적 공개 벤치마크 | 47,382 | 1,072 | 1,693 | CQADupStack Unix의 기존 커뮤니티 중복 질문 판정 |
| 최근 사례 추가 통제 시험 | 47,463 | 100 | 109 | 실제 StackExchange 질문의 `closed_details.original_questions` |

[CQADupStack 원 논문](https://doi.org/10.1145/2838931.2838934)과 [원 저자 저장소](https://github.com/D1Doris/CQADupStack)는 StackExchange의 실제 질문·중복 판정을 사용하는 자료의 근거다. [BEIR](https://github.com/beir-cellar/beir)에서 사용하는 Unix 도메인의 [MTEB 고정 스냅샷](https://huggingface.co/datasets/mteb/cqadupstack-unix/tree/3197b09145642430d9db451fcdc1e1987e54d74c)을 내려받았다. 원본 파일의 리비전·크기·SHA-256은 [source-manifest.json](../eval/vector-v2-real/source-manifest.json)에 있다.

정답 문서가 여러 개인 질문은 271개다. 모든 관련 문서를 정답 집합으로 사용했다. 제목·본문·기존 정답 관계를 모델로 다시 쓰지 않았다. 역사적 자료의 본문은 이미 줄바꿈이 평탄화돼 있으며, 원시 운영 로그 자체가 아니다. 문서 길이 중앙값은 제목 포함 612자, 95백분위 약 2,791자, 최대 32,623자다. `$ `가 포함된 본문은 4,283개, `possible duplicate` 문구가 있는 본문은 334개다. 전처리와 중복 표식까지 포함된 벤치마크라는 한계를 남긴다.

## 2. 학습 자료 중복을 발견해서 추가 시험을 만들었다

[all-MiniLM-L6-v2 모델 카드](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2)는 StackExchange 질문·답변뿐 아니라 중복 질문 쌍을 학습 자료로 명시한다. 공개 학습 설정에 적힌 중복 제목 쌍 파일 304,525개를 실제로 내려받아 대조했다.

- 역사적 평가의 정답 관계 1,693개 중 **527개**가 공개 학습 자료와 제목 쌍이 정확히 일치했다. 질문 기준 **498/1,072개**다.
- HTML 엔티티·대소문자·연속 공백을 정규화하면 **530개 관계, 500개 질문**이 일치했다.
- 따라서 역사적 벤치마크 점수를 **학습 자료와 독립된 일반화 성능**으로 사용하지 않는다.
- 이 일치는 공개 학습 자료와의 중복 증거다. 해당 모델의 실제 학습 배치에서 개별 항목이 소비됐다는 직접 증명은 아니다. 불일치하는 나머지도 다른 학습 출처까지 깨끗하다는 뜻은 아니다.

[중복 감사 결과와 파일 해시](../eval/vector-v2-real/training-overlap-audit.json)를 보존했다. 기존 점수나 정답을 바꾸지 않고, 문제를 발견한 후 별도 추가 시험을 설계했다. 이 추가 시험은 최초 계획에 있던 공식 BEIR 분할이 아니라 **명시적으로 기록한 후속 실험**이다.

## 3. 최근 실제 사례 100개의 결과

추가 수집 전에 [수집 규칙](../eval/vector-v2-real/recent-control/acquisition-plan.json)을 고정했다. 2022년 이후 작성된 닫힌 Unix 질문 중 생성일 내림차순 500개를 수집하고, 커뮤니티가 원래 질문을 지정한 중복 질문 100개를 선택했다. 검색 점수로 사례를 고르지 않았다. 실제 선택된 질문의 최초 작성일은 **2025-03-27~2026-11-16**이다.

100개 질문의 관련 기록은 105개, 정답 관계는 109개다. 이 105개 기록은 모두 답변이 있고 83개에는 채택 답변이 있다. 답변 본문 자체는 검색·채점에 사용하지 않았다. 정답은 [공식 API의 중복 대상 필드](https://api.stackexchange.com/docs/types/closed-details)를 그대로 사용했다. [각 질문과 정답 원문 링크·날짜·해시](../eval/vector-v2-real/recent-control/dataset-manifest.json)를 공개한다.

모델이 명시한 [2021년 StackExchange 학습 덤프](https://huggingface.co/datasets/flax-sentence-embeddings/stackexchange_xml)보다 나중에 작성된 질문이며, 앞서 확인한 304,525개 학습 제목 쌍과의 정규화 일치는 **0개**였다. 다른 모든 학습 데이터와의 비중복까지 증명한 것은 아니다.

후보는 기존 47,382개 기록에 현재 원문으로 확인한 정답 기록을 합친 **47,463개**다. 기존 ID 24개는 현재 본문으로 갱신하고 새 ID 81개를 추가했다. 자신의 질문 ID는 검색 후보에서 제외했다. 최신 방해 문서까지 무작위로 수집한 전체 운영 코퍼스는 아니다.

| 방식 | nDCG@10 | Recall@5 | Hit@1 | MRR@10 |
|---|---:|---:|---:|---:|
| 벡터(all-minilm) | 34.04% | 40.50% | 21.00% | 29.43% |
| BM25 | 19.38% | 21.50% | 13.00% | 17.15% |
| RRF 혼합 | 31.60% | 39.00% | 20.00% | 28.05% |

nDCG@10은 정답을 얼마나 높은 순위에 배치했는지를 0~1로 정규화한 지표를 백분율로 표시한 값이다. 예를 들어 34.04%를 “문제 해결 정확도 34.04%”라고 설명하면 안 된다. Recall@5는 각 질문의 전체 관련 문서 중 상위 5개에서 찾은 비율의 평균이며, Hit@1은 첫 결과가 관련 문서인 질문의 비율이다.

질문 단위 paired bootstrap 2,000회, 95% 구간:

- 벡터 − BM25 nDCG@10: **+14.66%p**, 구간 **+7.85~+21.85%p**.
- 혼합 − BM25: **+12.22%p**, 구간 **+7.40~+17.02%p**.
- 벡터 − 혼합: **+2.44%p**, 구간 **−3.88~+9.30%p**. **이 표본에서 벡터와 혼합의 우열은 확정하지 않는다.**

이 구간은 해당 표본의 질문 재추출에 따른 불확실성이다. 질문의 독립성을 가정하며, 공유 정답·주제 상관관계, 수집 편향, 다중 비교, 실제 서버 분포 차이를 제거하지 않는다. 최근 100개에는 bash 태그가 39개 있고, 미리 정한 운영 제목 정규식에 맞는 질문은 10개뿐이다. **홈서버 장애 전체를 대표하는 100개라고 말하지 않는다.**

## 4. 역사적 벤치마크 결과와 규모 효과

아래는 기존 공개 관련성 판정에 따른 관측 점수이며, 앞서 밝힌 학습 자료 중복 때문에 독립 일반화 성능으로 해석하지 않는다.

| 방식 | nDCG@10 | Recall@5 | Hit@1 | MRR@10 |
|---|---:|---:|---:|---:|
| 벡터(all-minilm) | 41.41% | 47.25% | 30.60% | 39.73% |
| BM25 | 28.59% | 31.16% | 24.16% | 28.64% |
| RRF 혼합 | 36.52% | 39.18% | 29.48% | 35.91% |

운영 관련 제목 정규식으로 사전 선택한 220개 질문의 전체 후보 nDCG@10은 벡터 **40.38%**, BM25 **26.75%**, 혼합 **34.30%**였다. 이 부분집합도 같은 학습 중복 위험을 공유한다.

후보 수 효과는 **같은 1,072개 질문과 같은 정답**을 유지하면서 비교했다. 모든 정답 문서 1,693개를 포함하고, 나머지는 ID 해시 순으로 추가해 후보 집합을 중첩시켰다. 축소 후보는 평가 정답을 알고 만든 통제 집합이며 실제 서비스의 문서 수집 절차나 공식 벤치마크 분할이 아니다.

| 후보 문서 수 | 벡터 nDCG@10 | BM25 nDCG@10 | 혼합 nDCG@10 |
|---:|---:|---:|---:|
| 5000 | 63.43% | 42.24% | 54.29% |
| 20000 | 49.97% | 33.09% | 42.74% |
| 47382 | 41.41% | 28.59% | 36.52% |


후보가 늘자 세 방식 모두 성능이 떨어졌다. 이 데이터에서는 5천 개일 때부터 벡터가 더 높았고, 벡터와 BM25의 격차는 오히려 줄었다. 따라서 **“문서 수가 커져서 벡터가 이겼다”는 단일 원인 설명은 근거가 없다.** 기존 합성셋과 달라진 언어·질문 표현·문서 구성도 함께 작용한다. v1과 v2의 점수 차이를 개선율로 계산하지 않는다.

## 5. 한국어 질문은 별도 문제였다

운영 관련 220개 중 질문 ID 해시 순으로 32개를 고르고, 첫 검색 점수를 보기 전에 제목만 한국어로 번역했다. 정답 관계와 영어 문서는 그대로다. 같은 32개 영어 원문과 비교했다.

| 방식 | 영어 원문 nDCG@10 | 한국어 번역 nDCG@10 |
|---|---:|---:|
| dense | 40.65% | 8.98% |
| bm25 | 29.24% | 2.55% |
| rrf | 37.11% | 8.55% |


이는 **한국어 질문 → 영어 기록**의 교차 언어 진단이다. 한국어 기록을 대상으로 한 검색 성능을 뜻하지 않는다. 번역은 작성한 통제 입력이며 독립적인 사람의 번역 검수는 없다. 현재 영어 중심 all-minilm과 키워드 검색만으로 한국어 운영 질의를 충분히 처리한다고 주장할 수 없다. 다국어 임베딩·질문 변환은 다음 별도 시험 대상이다.

## 6. 구현과 검증

- Dense: 기존 `all-minilm:latest`의 다이제스트를 고정하고 Ollama에서 실제 임베딩을 계산했다. 384차원, 정확한 코사인 검색이다. 실행 당시 Ollama가 전체 모델 크기와 동일한 VRAM 사용량을 보고했다. 벡터 생성은 로컬 모델, 순위 계산은 NumPy를 사용했다.
- BM25: `k1=1.2`, `b=0.75`, 명시한 양수 IDF, 소문자화와 고정 토큰화, 어간 추출·불용어 제거 없음. 수식을 직접 구현한 비교 기준이며 Elasticsearch/Lucene 공식 실행 결과는 아니다.
- RRF: Dense와 BM25 상위 100개를 같은 가중치, `k=60`으로 결합. 점수 확인 후 가중치를 조절하지 않았다.
- Dense는 **실제 실행 컨텍스트 256토큰**, BM25는 전체 본문을 사용한다. 모델 최대 메타데이터 512와 실행 옵션 256이 다르다는 점을 첫 점수 계산 전에 발견해 [정정 기록](../eval/vector-v2-real/protocol-amendment.json)에 남겼다. 정확히 몇 문서가 잘렸는지는 측정하지 않았다.
- 역사적 시험의 **9,744개 검색 결과 행, 질문별 지표 68,208개**를 `ir_measures 0.4.3 / pytrec_eval-terrier 0.5.11`로 교차 검증했다. 집계와 paired bootstrap도 재계산했다.
- 최근 시험의 **300개 검색 결과 행, 질문별 지표 2,100개**도 같은 외부 지표 구현과 일치했다. 자기 질문 검색 제외와 후보 ID 유효성도 확인했다.
- 역사적 전체 벡터 47,382개를 네트워크 없는 임시 PostgreSQL 16.16 / pgvector 0.8.7에 넣었다. 사전 선택한 영어 32개·한국어 32개에서 실제 SQL 상위 10개 순위가 **64/64 완전히 일치**했다. 임시 DB는 삭제했다. 이 SQL 확인은 최근 추가 시험 전체나 Spring AI 요청 경로·HNSW를 실행한 검증은 아니다.

위 검증은 **측정 계산과 구현이 맞는가**를 뒷받침한다. 정답 판정의 완전성, 운영 환경 대표성, 모델 학습과의 완전한 독립성을 증명하지 않는다. 커뮤니티의 중복 판정은 유용한 외부 근거지만 누락된 관련 문서가 있을 수 있고 모든 답변이 정확하다는 보장은 아니다. 정답 없는 질의의 검색 거절, 해결책 평가, Docker/Kubernetes/Prometheus 등 현대 홈서버 장애 전반은 이번 시험 범위 밖이다.

## 7. 비용·재현·면접 답변

유료 LLM API와 LLM Judge 호출은 **0회**, 외부 모델 API 비용은 **$0**다. 로컬 임베딩은 총 **48,691개 입력 / 1,523회 요청**이었다. 역사적 입력 48,486개는 약 9분 35초의 벽시계 시간에 완료했고, 최근 추가 입력은 205개였다. 전력·로컬 GPU 사용까지 비용이 없다는 뜻은 아니다. 공개 원문을 읽기 위한 HTTP 요청은 별도로 있었다.

[실행 및 재검증 방법](../eval/vector-v2-real/README.md), [역사적 결과](../eval/vector-v2-real/runs/real-v1/summary.json), [최근 추가 결과](../eval/vector-v2-real/recent-control/summary.json)를 제공한다. 원문·학습 원자료·벡터 캐시는 로컬에 보관하고, 공개 저장소에는 코드·규칙·ID·출처 링크·해시·숫자 결과를 남긴다. 최근 시험의 점수는 모델이나 원문 API 없이 공개 파일만으로 재계산할 수 있다.

최근 사례의 고정 원문 캐시는 공개하지 않으므로, 외부에서 완전히 동일한 원문으로 임베딩을 재실행하는 것은 보장하지 않는다. 원문 URL의 현재 내용은 수집 시점과 달라질 수 있다. 역사적 시험은 고정된 MTEB 스냅샷으로 전체 재실행이 가능하고, 최근 시험은 공개 파일로 숫자 채점을 완전히 재현할 수 있다는 차이가 있다.

면접에서는 다음처럼 설명할 수 있다.

> 처음에는 40개 합성 문서에서 BM25가 높았지만, 그 결과를 운영 성능으로 일반화하기 어렵다고 판단했습니다. 실제 Unix/Linux 질문 4.7만 건과 기존 커뮤니티 관련성 판정을 이용해 재평가했고, 모델 학습 자료와 제목 쌍이 겹치는 문제까지 발견했습니다. 그래서 최근 실제 질문 100개와 커뮤니티가 지정한 109개 정답 관계로 추가 시험을 했습니다. 확인한 공개 학습 제목 쌍과는 겹치지 않았고, nDCG@10은 벡터 34.0%, BM25 19.4%, 혼합 31.6%였습니다. 채점은 LLM의 주관적 판단 대신 공개 정답 관계와 검색 지표로 수행하고, 외부 지표 라이브러리로 재검산했습니다. 이 결과는 검색 성능이며 자동 복구 성공률은 아닙니다. 벡터와 혼합의 차이, 한국어 교차 언어 검색, 현장 대표성에는 한계가 남아 있다고 설명합니다.
