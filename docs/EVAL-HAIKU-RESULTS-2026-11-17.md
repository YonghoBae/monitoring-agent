# Haiku 5.5 채점 검증 결과

**Haiku 5.5의 전체 160건 재채점은 완료하지 않았다. 검증 게이트 실패로 중단했으며, 최종 점수나 순위를 주장하지 않는다.** 모델에 정답·관측을 주는 것만으로 채점의 일관성이 보장되지 않는 사례를 실제로 확인했다.

## 실제 사용량과 비용

| 호출 목적 | 횟수 |
|---|---:|
| 첫 캠페인 검증 | 20 |
| 첫 캠페인 본 답변 검토 | 29 |
| 의미 판정을 보존한 인용 형식 보정 | 2 |
| 두 번째 캠페인 검증 | 4 |
| 합계 | 55 |

응답 usage 합계는 입력 **118,173토큰**, 출력 **53,610토큰**, 캐시 읽기/쓰기 0이다. 모델 목록 조회는 이 추론 호출 수에 포함하지 않는다.

`118173 × $0.10/1,000,000 + 53610 × $0.50/1,000,000 = $0.0386223`

이는 [공식 Haiku 5.5 표준 단가](https://platform.claude.com/docs/en/models/haiku-5-5/overview)와 응답 usage를 이용한 추정 API 사용료다. 세금·계정 크레딧 구매·최종 청구액은 별개다. 두 캠페인을 합산한 $2 상한을 넘지 않았으며, 불명확하게 처리 중인 요청은 0개다. 추가 호출은 실행하지 않는다.

## 중단 이유

첫 검증 20건은 모두 사전 판정과 일치했다. 이후 본 답변 29건을 검토하던 중 Haiku가 DNS 지표의 존재와 정답의 모순을 지적했다.

실제로는 `list_metrics(filter)`가 필터된 목록을 반환하지만, 기존 NumericEvalWorld 기록기가 `match[]`를 버리고 `/api/v1/label/__name__/values`라는 경로만 남겼다. Haiku는 이를 필터 없는 전체 목록으로 해석했다. 원본 fixture에는 `probe_dns_lookup_time_seconds`가 있고 다른 arm의 실제 관측도 5.1초를 반환한다. 이 경우는 gold를 고칠 문제가 아니라 **평가자의 입력 계약을 고칠 문제**다.

첫 캠페인 결과를 최종 집계에서 제외하고, 모든 답변에 동일하게 trace의 필터 누락 사실과 참조 메트릭 목록을 제공하는 새 입력을 준비했다. 참조 목록은 에이전트가 실제 조회한 근거와 명확히 구분했다.

두 번째 검증에서는 다음의 동일한 답변에 다른 판정이 나왔다.

| 항목 | 내용 |
|---|---|
| 관측 | available_bytes = 8,000,000,000 |
| 요청 | 십진 GB 단위의 여유 공간 |
| 답변 | `여유 공간은 약 7.45058 GiB입니다.` |
| 사전 채점 규칙 | 명시적으로 맞는 단위의 동등 물리량은 변환 허용. 7.45058 GiB는 약 8 GB이므로 허용 오차 내 정답 |
| 첫 호출 | 8로 정규화, 근거 인정, 통과 |
| 두 번째 호출 | 7.45058을 그대로 비교하고 GiB라는 이유로 오답·단정 오류 처리 |

이 두 검증 요청의 system과 payload는 동일하다. 두 번째 호출은 첫 호출 결과를 보지 않았다. 규칙 위반이 확인됐으므로 사전 20/20 게이트에 따라 전체 실행을 멈췄다. 한 번의 불일치로 Haiku의 전체 오판율을 추정할 수는 없지만, 이번 채점 방식의 반복 일관성이 입증되지 않았다는 근거는 된다.

## 보관 및 수정

- 원래 160개 에이전트 답변, 기존 Codex 점수, 기존 데이터는 변경하지 않았다.
- [첫 캠페인](../eval/haiku-review-20261117/manifest.json), [두 번째 캠페인](../eval/haiku-review-20261117-v2/manifest.json)에 입력·코드 해시가 있다. 각 디렉터리의 `requests.jsonl`, `raw/`, `cost.json`에 실제 호출·응답·비용이 있다.
- 원문에 없는 인용은 그대로 받아들이지 않았다. 두 건의 별도 형식 보정은 추출값·판정·근거 ID·단정 목록을 바꾸지 못하도록 검사했으며, 원본 응답도 보존했다.
- 이후 평가에서 검색 범위를 잃지 않도록 NumericEvalWorld가 탐색 URL의 `match[]`를 기록하도록 수정했다. 과거 원본의 누락된 필터 값을 지어내서 복원하지 않았다.
- 로컬 Python 검사 16개와 실제 Prometheus 기반 NumericEvalWorld 통합 검사 1개가 통과했다. 테스트용 컨테이너 정리와 Git 공백 검사도 확인했다. 운영 서비스 배포는 수행하지 않았다.
- 전체 평가에서 값을 추출하고 단위를 맞추는 일까지 자유로운 LLM 판단에 맡기면 변동이 생길 수 있다. 다음 실행 전에는 수치·단위 정규화를 코드로 분리하고, 별도 검증 집합에서 반복 판정 일관성을 확인하는 보강이 필요하다. 이 보고서는 그 보강을 완료했다고 주장하지 않는다.

다른 모델 계열로 채점한 점은 의미가 있지만, 데이터셋 대표성이나 독립 사람 검수를 대체하지 않는다. 기존 76.7점을 검증해 확정한 결과도 아니다.
