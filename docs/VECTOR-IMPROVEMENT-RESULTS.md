# 공개 질문 기반 벡터 검색 개선 결과

**한국어 질문으로 영어 기록을 찾는 성능은 개선됐다. 영어 검색까지 포함한 전면 교체 근거는 얻지 못했다.** 개발 평가에서 선택한 Qwen3 임베딩·리랭커 조합이 새로운 출처의 영어 시험에서는 기존 MiniLM을 넘지 못했고 리랭커의 지연도 컸다. 운영 모델과 검색 설정은 변경하지 않았다.

2026-11-18 KST 완료된 검색 단계 실험이다. nDCG는 관련 문서의 순위 지표이며 답변 정확도·장애 원인 진단·복구 성공률이 아니다. 이번 검색 채점에는 LLM Judge를 사용하지 않았다.

## 최종 시험 결과

모든 방법에 **문서 48,235개**를 동일하게 제공하고 질문 자신은 후보에서 제외했다. 새 영어 원문 질문 **91개** 중 고정한 20개를 한국어로 번역했다. 독립 사례가 111개인 것은 아니다. Hit@5는 알려진 관련 문서가 상위 5개 중 하나라도 있는 질문 수다.

| 방법 | 영어 91개 nDCG@10 | 영어 Hit@5 | 한국어→영어 20개 nDCG@10 | 한국어→영어 Hit@5 |
|---|---:|---:|---:|---:|
| 기존 all-minilm | **0.3056** | **33/91** | 0.0857 | 3/20 |
| BM25 | 0.1972 | 22/91 | 0.0802 | 3/20 |
| Qwen3-Embedding-0.6B | 0.2337 | 28/91 | 0.3617 | **10/20** |
| Qwen 임베딩 + Qwen3-Reranker-0.6B, 상위 50개 재정렬 | 0.2870 | **33/91** | **0.3663** | **10/20** |

기존 대비 nDCG@10 차이의 95% 구간은 공유 정답으로 연결된 질문을 묶는 paired cluster bootstrap 2,000회로 계산했다. 영어는 80개, 한국어는 17개 묶음이다. 두 언어는 별도로 계산했고 정답표 누락·번역 편향은 이 구간으로 보정되지 않는다.

| 비교: 기존 MiniLM 대비 | 평균 차이 | 95% 구간 |
|---|---:|---:|
| 영어, Qwen 임베딩 | −0.0720 | [−0.1258, −0.0220] |
| 영어, Qwen 전체 조합 | −0.0186 | [−0.0778, +0.0403] |
| 한국어→영어, Qwen 임베딩 | +0.2760 | [+0.1011, +0.5033] |
| 한국어→영어, Qwen 전체 조합 | +0.2806 | [+0.1023, +0.5040] |

이 표본에서 영어 임베딩 단독은 퇴보했다. 전체 조합도 영어 우위를 입증하지 못했다. 한국어→영어 개선 방향은 일관되지만 20개 번역 질문의 결과를 모든 한국어 운영 로그에 일반화할 수 없다.

**같은 20개 질문의 영어 원문과 한국어 번역**으로 대조하면, MiniLM의 nDCG@10은 영어 0.4041→한국어 0.0857, Qwen 임베딩은 0.3488→0.3617이었다. 이번 개선이 언어 간 검색과 관련 있다는 관찰이며 언어별 자동 라우팅을 검증했다는 뜻은 아니다.

## 데이터와 근거

개발 기반은 [CQADupStack](https://github.com/D1Doris/CQADupStack)의 [Unix 자료](https://huggingface.co/datasets/mteb/cqadupstack-unix)와 최근 Unix 질문이다. 커뮤니티 중복 링크를 관련 문서의 근거로 쓸 수 있고 Linux·네트워크·패키지·디스크 등 운영과 겹치는 주제가 있다. 이전 평가에서 공개 학습 자료와 질문 쌍 중복을 발견했기 때문에 과거 점수를 새로운 사례에 대한 성능으로 취급하지 않았다.

최종 시험은 [Stack Exchange API](https://api.stackexchange.com/docs/advanced-search)로 수집한 Ask Ubuntu 59개, ServerFault 9개, Super User 23개다. 생성일은 2025-08-13~2026-10-28로 다섯 후보 모델의 실제 가중치 파일 공개보다 뒤다. 다운로드 SHA와 공식 LFS OID도 일치했다. 기존 글의 재인용이나 이전 지식까지 없다는 증명은 아니다.

정답 문서 98개에는 모두 답변이 있고 60개에는 채택 답변이 있다. 91개 질문 중 59개가 채택 답변이 있는 정답으로 연결된다. **실제 사용자 질문이지만 모두 검증된 장애 복구 기록은 아니다.** 데스크톱·WSL·설정 질문도 포함되므로 홈서버 운영 전용 평가라고 부르지 않는다.

질문 제목만 검색어로 사용하고 문서 제목과 본문을 검색했다. 한국어 20개는 작성한 번역이며 실제 한국어 운영 로그가 아니다. 번역은 첫 개발 점수 전에 고정했지만 인코딩은 이미 시작됐으므로 전체 추론 이전의 엄격한 사전등록은 아니다. 최종 점수 전에 원문과 대조했으나 독립 사람 검수는 아니다.

## 후보 선택

GTX 1050 Max-Q 4 GiB에서 다국어 임베딩 세 종류와 리랭커 두 종류를 비교했다. 공식 prefix·pooling·리랭커 입력 형식을 적용했다. BGE는 dense 표현만 사용했다. 임베딩 최대 256토큰, 리랭커는 wrapper 포함 최대 512토큰이며 모델별 토크나이저·형식이 달라 읽은 원문 길이가 동일한 비교는 아니다.

개발 문서는 5,000개, 질문은 최근 영어 100개와 과거 영어 32개 및 그 한국어 번역 32개다. 선택 기준은 **최근 영어 nDCG@10 50% + 한국어 번역 nDCG@10 50%**다. 실제 트래픽 비중이 아니라 실험의 우선순위이며 과거 영어 32개는 진단용이다.

| 개발 조건 | 선택 점수 |
|---|---:|
| MiniLM | 0.3794 |
| BM25 | 0.2405 |
| multilingual-e5-small, query/passage | 0.4239 |
| E5 query/query | 0.4419 |
| BGE-M3 dense | 0.5645 |
| Qwen3-Embedding-0.6B | 0.6669 |
| Qwen 앞·뒤 부분 입력 | 0.6595 |
| MiniLM + BGE-reranker-v2-m3, 20개 | 0.3881 |
| Qwen + BGE 리랭커, 20개 | 0.6103 |
| MiniLM + Qwen3-Reranker-0.6B, 20개 | 0.4536 |
| Qwen + Qwen 리랭커, 20개 | 0.7034 |
| **Qwen + Qwen 리랭커, 50개** | **0.7152** |
| Qwen + Qwen 리랭커, dense 25개와 BM25 25개 합집합 | 0.7069 |

앞·뒤 입력은 제한된 두 조각의 최대 점수이며 전체 문서 청킹이 아니다. 합집합은 중복 제거 후 최대 50개다. 낮은 점수도 삭제하지 않았다. 한 조합만 전체 문서 최종 시험에 올렸으므로 모든 모델의 최종 순위를 매긴 실험은 아니다.

선택은 UTC 16:09:58에 [잠갔고](../eval/vector-v3-improvement/final-selection-lock.json), 최종 점수 산출 전 [공개 커밋 436743f](https://github.com/YonghoBae/monitoring-agent/commit/436743fafef38327fc33febc0f4c5fb223a3247d)에 계획·개발 결과·선택을 게시했다. 최종 점수를 보고 다른 조합을 다시 고르지 않았다.

개발의 최근 Unix 영어 100개는 후보를 48,235개로 늘린 대조에서도 MiniLM 0.3343, Qwen 0.3734, 전체 조합 0.3880이었다. 새로운 세 출처의 영어 91개에는 개선이 유지되지 않았다. 문서 수뿐 아니라 출처·질문 분포가 다른 곳으로 성능이 옮겨가는지도 시험해야 한다. 퇴보 원인은 이 실험만으로 확정할 수 없다.

## 실패 분석과 후속 가설

최종 조합의 영어 91개 중 39개는 재정렬할 상위 50개에 알려진 정답이 없었다. 나머지 중 33개는 정답 후보가 있었지만 첫 결과로 올리지 못했다. 한국어 20개에서는 각각 7개와 9개였다. 후보 검색과 재정렬 양쪽에 개선 여지가 있으며 후보에 없는 정답을 리랭커로 복구할 수는 없다.

별도로 고정한 중복 링크 그래프를 대조하니 최종 조합의 첫 결과 중 영어 4개·한국어 1개가 정답표에는 없지만 같은 중복 연결망에 속했다. **정답 누락 가능성 표시**이며 실제 관련성 판정은 아니다. 사후 정답으로 추가하거나 점수를 올리지 않았다. [실패 분석](../eval/vector-v3-improvement/final/error-analysis.json)에 남겼다.

후속으로 실제 한국어 운영 기록과 넓은 정답 검토, 긴 문서 청킹·검색 필드 분리, 언어·도메인별 검색 방식, 후보 재현율 개선을 별도 개발 자료에서 시험할 필요가 있다. 아직 검증되지 않은 가설이다. 이번 최종 질문으로 다시 튜닝한 점수를 독립 시험 점수라고 제시하면 안 된다.

## 실행 비용과 운영 판단

GTX 1050 Max-Q 4 GiB에서 Qwen 임베딩 새 입력 43,346개 인코딩에 약 **125.8분**이 걸렸고 개발 벡터 5,164개를 재사용했다. 기존 모델은 훨씬 많은 캐시를 재사용했으므로 작업 시간을 그대로 모델 속도 비교에 쓰지 않는다.

로드된 리랭커의 후보 50개 처리 시간을 20개 질문에서 측정했다. 중앙값 **16.79초**, p95 **19.79초**다. 한국어 nDCG@10은 임베딩 단독 0.3617→리랭커 포함 0.3663으로 조금 늘었고 Hit@5는 동일했다. Hit@1은 5/20→4/20으로 줄었다. 이 하드웨어에서는 이득 대비 지연이 크다.

두 Qwen 모델의 최대 GPU allocated 메모리는 각각 약 2,320 MiB와 2,392 MiB였다. 개별 실행과 두 모델·답변 LLM의 동시 실행은 다르다. 모델 순차 로드와 인메모리 전체 검색을 포함한 고정 질문 6개는 중앙값 **20.70초**, 범위 **16.62~23.04초**였고 저장된 상위 10개 순서와 6/6 일치했다. warm filesystem 조건이며 서버·DB 요청·답변 LLM·동시 부하는 제외했다. 신뢰할 만한 p95를 추정할 표본 수는 아니다.

**운영 전면 교체나 리랭커 상시 적용은 권하지 않는다.** 한국어→영어 검색의 가능성은 확인했지만 실제 한국어 기록과 운영 지연을 추가 검증해야 한다. 384→1,024차원 교체에는 재임베딩·새 인덱스·유사도 임계값 재보정도 필요하다. 유료 API 호출은 **0건**이고 전기·호스트 비용은 측정하지 않았다.

## 기존 한국어 합성 자료 회귀

원래 합성 자료는 20개 문제 유형, 문서 40개, 답할 수 있는 질문 변형 60개다. 최종 선택 후 회귀만 확인했다. 정답 없는 8개 질문은 제외했고 리랭커·무응답 임계값은 시험하지 않았다.

| 한국어 질문 40개 | 전체 기록 40개: nDCG@10 / Hit@5 | 해결 기록 20개만: nDCG@10 / Hit@5 |
|---|---:|---:|
| MiniLM | 0.6063 / 28/40 | 0.6524 / 28/40 |
| BM25 | 0.6691 / 33/40 | 0.8520 / 34/40 |
| Qwen 임베딩 | 0.8768 / 40/40 | 1.0000 / 40/40 |

작은 합성 자료의 만점은 실서비스 정확도가 아니다. 후보 종류에 따라 점수가 바뀌며 이 결과로 실제 공개 질문의 영어 퇴보를 상쇄하지 않는다. [전체 회귀 결과](../eval/vector-v3-improvement/native-regression.json)에는 영어→한국어 대조도 포함했다.

## 검증 범위와 한계

- 외부 IR 구현으로 **23,704개 지표 값**이 일치했다. 개발 14,924개, 전체 문서 평가 7,700개, 합성 회귀 1,080개다. 독립 표본 수가 아니라 계산 검증 수다. 순위 3,592행, 선택 규칙, 고정 파일 hash, 집계와 군집 bootstrap을 재검산한다.
- 관련 로컬 테스트 22개가 통과했다. CPU 검증은 Torch가 필요한 캐시 테스트 2개를 제외한 20개와 수치 재현을 실행한다. 자동화 정의만으로 원격 CI 성공을 주장하지 않으며 실제 실행 상태는 [Actions](https://github.com/YonghoBae/monitoring-agent/actions/workflows/vector-evidence.yml)에서 확인한다.
- 격리된 PostgreSQL 16.16 / pgvector 0.8.7에 48,235개 벡터를 넣어 exact cosine 상위 10개가 **36/36 일치**했다. ANN 인덱스, Spring AI/API 연결, 운영 DB를 검증한 것은 아니다.
- 질문·정답 ID, 문항별 점수, 압축 순위, 설정·모델 revision·파일 hash를 공개한다. 원문 게시물 전체, 모델 가중치, 운영 로그·비밀값은 제외한다. 숫자 재검증은 GPU·모델·API 키가 필요 없고 추론 재실행은 원문 획득·가중치·GPU가 필요하다.

이는 계산 오류·시험 후 선택 변경·일부 학습 중복 위험을 줄이는 근거다. 정답표 완전성, 대표성, 실제 한국어 장애 사례, 독립 사람 검수, 답변 품질까지 증명하지 않는다. [방법·재현 명령](../eval/vector-v3-improvement/README.md), [수치 검증 기록](../eval/vector-v3-improvement/numeric-verification.json), [DB 검증](../eval/vector-v3-improvement/final/pgvector-verification.json)을 함께 공개한다.

## 면접에서 설명한다면

> 작은 합성 데이터의 높은 검색 점수를 그대로 믿지 않고 공개 Unix 질문과 커뮤니티 중복 링크로 평가를 확장했습니다. 학습 자료 중복 위험을 발견한 뒤 모델 가중치 공개 이후 새 질문을 확보하고, 개발 자료에서 13개 조건을 비교해 선택을 잠근 후 시험했습니다. 검색 평가는 LLM Judge 대신 관련 문서 ID와 nDCG·Hit 지표를 사용했고, 외부 라이브러리 재계산과 군집 bootstrap으로 검증했습니다. Qwen으로 한국어→영어 검색 Hit@5는 3/20에서 10/20으로 개선됐지만 영어에는 일반화되지 않았고 리랭커도 약 17초가 걸려 운영 교체는 보류했습니다. 개선과 실패를 모두 남겨 실제 적용 조건을 구분한 실험입니다.
