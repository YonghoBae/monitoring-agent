The wrong-number control requested decimal GB, observed 1,073,741,824 bytes, and answered `1`. Code marked the answer outside tolerance and the judge rejected the finding. Its unsupported reasoning nevertheless treated the wrong scalar as an ordinary answer error rather than an unsupported factual assertion. One response explicitly stated there were no unsupported claims beyond the value itself. That interpretation consistently disagreed with the original expected unsupported label. This is a boundary-definition problem, not a failure of deterministic arithmetic; the original gate remains failed.

The malformed wrong-entity response correctly explained that its observation concerned a different node and that the answer's attribution was unsupported, but a stray quoted brace made the response unparsable. Similar malformed output affected another entity/window control and a Boolean-for-status-code control. Semantic plausibility cannot rescue malformed output under the frozen gate. The separate quote failure likewise remains invalid; decoding or rewriting an overescaped answer quote after the fact would be a repair forbidden by this run's protocol.

The next version should make the policy and response representation explicit before fresh independent controls are exposed to its implementation author:

1. Preserve deterministic numeric checks and the AND composition with semantic grounding. Define incorrect asserted requested facts as unsupported, including a wrong numeric assertion identified by the authoritative numeric check. Pure JSON, missing-key, type or extraction failures do not automatically establish a separate unsupported factual assertion. Unknowns remain distinct from omissions, and code pass never proves correct entity, interval or evidence association.
2. Use a new versioned transport helper with a strict structured-output schema. Keep the existing helper, validated canonical judge, campaign and all failed artifacts unchanged. Boolean labels, answer status, exact allowed fields and observation IDs should be constrained by the schema where supported and validated again locally.
3. Build answer-quote candidates deterministically from the original answer: empty string, exact nonempty lines, and the whole answer, with duplicate candidates removed. Every candidate must be an exact contiguous substring. A dynamic string enum lets the structured-output mechanism handle JSON escaping without asking the judge to reconstruct a quoted JSON fragment. A satisfied finding still requires a nonempty exact quote. No arbitrary fallback, rewriting or semantic repair is allowed.
4. Keep exact finding coverage explicit. An array length and field-key enum alone do not guarantee each required key appears once. The implementation must use a supported schema representation that guarantees this or retain a strict local validator that rejects duplicate or omitted findings; it must not claim stronger guarantees than it implements.
5. Reuse the same new production payload builder, transport schema and final composition in validation. Freeze fresh independent controls and their manually authored labels before evaluation. The implementation author must not read those controls while developing the new policy or transport. Old failed controls may remain diagnostic regression material; they cannot be reinterpreted as a successful independent gate.
6. Preserve the exact all-judgments gate, no-retry rule, paid ledgers, global budget reservation and immutable artifact identities. A transport fix does not justify omitting invalid responses, dropping hard controls, changing labels, averaging away inconsistency or automatically increasing the evaluation budget.

The next validation is a new gate, not a rerun of this one. Its outcome must remain separate from both this failed campaign and the canonical eight-case comparison. No new broad answers should be collected or graded as trusted metrics until the new source, code and empirical validation gates are satisfied.
