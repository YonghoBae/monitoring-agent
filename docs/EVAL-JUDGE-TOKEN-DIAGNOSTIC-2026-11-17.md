## 변경 범위와 보존

- 모델 `claude-haiku-5-5`, effort `medium`, 시스템 프롬프트, 사용자 입력, 구조화 출력 스키마를 유지했다.
- 요청 본문의 `max_tokens`만 4,096에서 16,384로 변경했다. API 타임아웃과 호출 방식도 그대로다.
- 16,384는 진단 프로세스 내부에서만 적용했다. 공통 채점기의 `MAX_OUTPUT = 4096` 기본값은 변경하지 않았다. 이 커밋을 가져오는 것만으로 본평가 설정이 바뀌지는 않는다.
- 원래 33개 요청을 재구성한 SHA-256이 기존 전송 원장과 일치하는지 확인했다. 실제 새 전송 33개도 사전 저장한 새 요청 해시와 일치한다.
- 에이전트 답변을 새로 생성하지 않았다. 원래 답변·관측·reference를 재사용했다.
- 각 선택 요청을 한 번만 호출했다. 자동 재시도나 실패 결과 덮어쓰기는 하지 않았다.
- 기존 평가 기록과 관련 실행 코드 등 649개 파일의 해시를 종료 후 확인했다. 모두 동일했다.
- 전역 예산 등록부에는 새 진단 경로 하나만 추가했다. 이전 등록부 원문은 진단 디렉터리에 별도 보존했고 $2 한도는 유지했다.

예산 사전 검사의 보수적 추가 예약액은 $0.3454669였다. 실제 비용은 API 토큰 사용량과 입력 $0.10/MTok·출력 $0.50/MTok의 단기 문맥 요율에 따른 추정이며 청구서 확정액은 아니다. [Anthropic 공식 요율](https://platform.claude.com/docs/en/about-claude/pricing)

## 해석과 다음 설정

이번 선택된 실패 요청에서는 16,384가 충분했다. 8,192를 넘겨 출력한 요청도 있으므로 다음 사전 검증의 기본 후보로 16,384를 유지할 근거가 생겼다. 전체 평가 분포에서 다시는 잘리지 않는다는 보증은 아니다.

33개 중 20개는 이번 재호출에서는 4,096 이하로도 완료했다. 기존 한도에서 재호출한 대조군은 없으므로 모든 정상화를 한도 변경만의 인과 효과라고 단정할 수 없다. 같은 입력의 생성 변동과 선택된 실패만 재시험한 효과를 구분해야 한다.

로컬 검증 통과는 형식·필수 항목·인용/관측 참조 조건을 만족했다는 뜻이다. 새 의미 판정이 독립 정답과 일치하는지 다시 교차 검수한 것은 아니다. 따라서 채점 완료율 개선을 채점 정확도 인증으로 해석하지 않는다.

기존 61.8 / 53.6 점수, 35개 무효 판정 기록, 미해결 38/210개라는 원래 보고는 그대로 보존한다. 이번 33개 결과를 기존 점수에 섞거나 최종 순위를 재계산하지 않았다. 새 설정의 비교 점수를 내기로 한다면 별도 검증·분석 계획 아래 양쪽에 같은 조건을 적용해야 한다.
