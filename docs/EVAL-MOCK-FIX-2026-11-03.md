# 잘못된 조회에 답하던 평가 mock 수정

기존 38종 데이터셋과 정답 기준은 보존했다. 운영 에이전트·프롬프트·컨테이너는 변경하지 않았다.

## 반영

- PromQL은 고정 버전 `promql-parser==0.11.0`으로 AST를 파싱한다. 문법 오류에 준비된 정상 수치를 주지 않는다.
- 선언된 메트릭 이름을 확인한다. `node_cpu_nonexistent_metric`이 `node_cpu`라는 단어를 포함해도 CPU 관측을 주지 않는다.
- fixture에 명시된 메트릭 레이블만 사용한다. 알람의 severity·instance 등을 모든 메트릭의 라벨로 추측해 복사하지 않는다.
- 알려진 대상과 불일치하면 빈 결과다. 레이블 사실 자체가 없으면 지원 불가로 구분한다.
- 이름이 비슷한 메트릭의 요약을 빌려오지 않는다. `node_load1`과 `node_load5`, 컨테이너 CPU와 메모리를 구분한다.
- 올바른 공백·따옴표·메트릭 이름 matcher의 대체 표기는 허용한다. 특정 정답 쿼리 문자열만 요구하지 않는다.
- 알람 검증은 알람 이름과 레이블이 맞을 때만 해당 상태를 반환한다. 잘못된 대상에 CONFIRMED를 돌려주지 않는다.
- 로그는 Docker source·정확한 컨테이너 이름·fixture inventory·시간 범위·limit을 확인한다. 문자열 일부가 같다는 이유로 다른 컨테이너의 로그를 주지 않는다.
- 고정 상태 도구의 잘못된 resource 값도 정상 전체 상태로 처리하지 않는다.
- Python helper와 parser 설정 변경이 Gradle 테스트 입력에 포함되게 했다.

## 계산할 수 없는 정상 쿼리

기존 데이터는 수치 시계열이 아니라 설명형 요약이다. 임의의 `rate`, 집계, 사칙연산 결과를 계산할 수 있는 데이터가 아니다.

따라서 단순 selector에 대응되는 관측을 찾으면 **관측 요약이며 PromQL 계산 결과가 아님**을 표시한다.
유효한 계산식, 필요한 라벨 정보가 없는 조회, 여러 시계열을 분리해야 하는 조회 등은 `unsupported_fixture`로 기록한다.

이 기록은 모델 실패나 Judge 파싱 실패가 아니다. `results.jsonl`에는 `evaluationStatus=ungraded_fixture`, `fixtureUnsupported`, `unsupportedQueries`를 남기고 Judge 채점을 건너뛴다.
하나라도 미판정이 있으면 실행 전체의 합격률 비교표를 만들지 않는다. 서로 다른 지원 범위로 v1/v2/v4 순위를 만드는 일을 막기 위함이다.

전체 PromQL 계산 평가를 하려면 수치 시계열 fixture와 계산 엔진을 추가해야 한다. 이번 수정은 이를 구현한 척하지 않고 잘못된 성공 응답부터 차단한 범위다. 호스트 로그 등 기존 inventory로 출처를 증명하지 못하는 관측도 미판정으로 남긴다.

## 검증

- Python 계약 검사 13개 통과.
- 기본 Java 테스트 84개 통과. 실제 Python parser를 호출하는 bridge 검사도 환경 변수를 지정해 실행했다.
- 잘못된 문법, 없는 메트릭, 불일치 대상, 알 수 없는 라벨, 알람 전용 라벨, 유효한 대체 표기, 서로 다른 메트릭, 복수 시계열, 잘못된 알람 검증, 로그 출처·개수, 미판정 시 비교표 금지를 검사했다.
- 기존 결과를 새 기준으로 덮어쓰거나 새 프롬프트 우열을 주장하지 않았다. 전체 모델 비교는 재실행하지 않았다.

설치·실행 방법은 [EVAL.md](EVAL.md)의 parser 준비 항목에 기록했다. parser가 없으면 라이브 평가가 오류로 종료하며 예전 느슨한 mock으로 되돌아가지 않는다.
