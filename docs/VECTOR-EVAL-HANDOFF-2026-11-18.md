# 벡터 검색 평가 handoff — 2026-11-18

## 중단 지점과 사용자의 의도

사용자는 작업을 끄고 나중에 재개할 예정이다. **새 평가를 시작하지 말고 이 기록에서 이어간다.** handoff 작성 시 실행 중인 벡터 평가 프로세스는 없었다. 운영 검색 모델·인덱스·설정은 변경하지 않았다.

사용자의 핵심 의문은 “정답 데이터셋도 대략 만든 것 아닌가, 실제로 잘 검색하는지를 평가하고 있는가?”다. 다음 우선순위는 모델을 더 바꾸는 것이 아니라 **정답표의 관련성·완전성과 실제 서비스 목적에 대한 적합성을 검증하는 것**이다. 사용자가 말한 가설에 맞춰 결론을 내리지 말고 반대 사례와 성공 사례도 확인한다.

## 가장 중요한 해석

- 정답 ID를 임의로 만든 것은 아니다. 공개 커뮤니티의 중복 질문 연결을 가져왔다.
- 그러나 관련 문서를 모두 판정한 정답표가 아니다. 다른 유용한 문서가 오답 처리될 수 있고, 등록된 정답도 질문의 구체적인 요구나 해결 가능성을 충족하는지 충분히 검토하지 않았다.
- 현재 Hit@5는 **알려진 중복 대상 문서를 상위 5개에서 찾은 비율**이다. 유용한 검색 결과를 제공한 비율, 원인 진단 정확도, 복구 성공률로 바꿔 말하면 안 된다.
- 수치 재검산·CI 통과는 계산의 일관성을 확인한다. 라벨 타당성·대표성·운영 유용성을 보증하지 않는다.
- v4에서 본문 추가로 점수가 오른 것은 기존 정답표 회수율이 개선됐다는 증거다. 실제 검색 품질이 같은 정도로 좋아졌다는 독립 증명은 아니다.

## 완료한 작업과 결과

### v3: 모델·리랭커 비교와 고정된 최종 시험

개발 단계에서 13개 조건을 비교했다. MiniLM 기준선, E5·BGE-M3·Qwen3 임베딩, BGE·Qwen 리랭커, E5 prefix, 문서 앞·뒤 조각, 후보 20/50개, dense/BM25 합집합을 포함한다. 가능한 모든 모델·청킹·필터 조합의 전수 시험은 아니다. 전체 후보 최종 시험에는 선택한 한 조합만 올렸다.

문서 48,235개, 새 영어 질문 91개(Ask Ubuntu 59 / ServerFault 9 / Super User 23), 그중 한국어 번역 20개다. 영어 문서를 검색하므로 한국어 결과는 한국어→영어 검색이다. 독립 사례 111개가 아니다. 정답 문서는 98개, 정답 연결은 109개다. 실제 질문이지만 모두 홈서버 장애 복구 기록은 아니다.

| 방법 | 영어 nDCG@10 / Hit@5 | 한국어→영어 nDCG@10 / Hit@5 |
|---|---:|---:|
| 기존 MiniLM | 0.3056 / 33/91 | 0.0857 / 3/20 |
| BM25 | 0.1972 / 22/91 | 0.0802 / 3/20 |
| Qwen 임베딩 | 0.2337 / 28/91 | 0.3617 / 10/20 |
| Qwen 임베딩 + Qwen 리랭커 top50 | 0.2870 / 33/91 | 0.3663 / 10/20 |

리랭커만의 중앙값 지연은 16.79초였다. 영어 우위가 없고 한국어 추가 이득도 작아 전면 교체·리랭커 상시 적용을 권하지 않았다. 원래 합성 40문서 회귀는 새 모델이 높게 나왔지만 운영 성능 증거로 쓰지 않는다.

개발 선택 기준은 최근 영어 nDCG와 과거 한국어 번역 대조군 nDCG를 50:50으로 반영했다. 실제 트래픽 비중이 아니다. 선택을 잠그고 최종 점수 전에 공개 커밋을 남겼다. 기존 학습 자료와의 중복 위험을 발견했으며 새 91개 질문은 비교 모델 가중치 공개 이후 생성됐다. 이전 지식·유사 문서 학습까지 없다는 증명은 아니다.

### v4: 사후 원인 진단

v3 점수·정답표를 유지하고 같은 영어 질문 91개에서 조건을 바꿨다. **이미 본 시험 자료를 재사용한 진단**이므로 새 독립 성능으로 제시하지 않는다.

| 모델·입력 | nDCG@10 | Hit@5 |
|---|---:|---:|
| MiniLM 제목 | 0.3056 | 33/91 |
| MiniLM 제목+질문 본문, native 256토큰 | 0.4018 | 44/91 |
| Qwen 제목 | 0.2337 | 28/91 |
| Qwen 제목+질문 본문, 256토큰 | 0.3717 | 43/91 |
| Qwen 같은 본문, 512토큰 | 0.3979 | 47/91 |

같은 문서 풀과 문서 벡터를 유지했다. 본문 추가는 두 모델 모두에 도움이 됐고, 같은 본문 조건에서 Qwen 우위를 입증하지 못했다. 본문에는 수집 당시 편집·사후 단서가 있을 수 있어 사건 발생 당시 입력이라고 보장하지 않는다. 정답 제목 문자열과 일치한 네 질문을 제외한 민감도에서도 개선은 유지됐다. 일부 일치 문자열은 일반적인 오류 문구여서 누출로 단정하지 않는다.

다른 가설도 시험했다.

- 질문과 벡터를 고정하고 모든 알려진 정답을 보존한 5,000문서 풀로 줄이면 MiniLM Hit@5 52/91, Qwen 49/91이었다. 후보 경쟁의 영향을 확인했으나 정답을 알고 구성한 축소 풀이라 운영 점수가 아니다.
- 해시로 고른 질문 32개의 정답+기존 상위 결과를 고정한 문서 표현 대조: 284문서, 전체 607조각. 앞 256토큰·앞 512토큰·전체 조각 최대 점수 모두 정답 1위 4/32였다. 청킹이 주원인 해결책이라는 근거는 이 제한된 대조에서 약했다. **정답을 강제로 후보에 포함했고 전체 48,235문서를 청킹한 실험은 아니다.**
- Qwen 지시문 제거는 Hit@5 28→21로 퇴보했다.
- BM25에 질문 본문을 추가하면 22→26/91이었다. 키워드 검색만으로 문제가 해결되지는 않았다.
- 캐시 SHA·벡터 차원·유한값·norm·기존 순위 재현이 정상이다. 두 모델의 상위 100개 순위가 각각 91/91 일치했다. Qwen 질문 재인코딩 결과도 사실상 같았다.
- 첫 CPU 진단의 batched 행렬곱은 한 질문 81·82위의 약 1e-7 차이를 만들었다. 원래 정규화·행렬-벡터 계산으로 맞추니 일치했다. 주 지표 영향은 없으며 기존 평가 버그가 아니다. 초기 코드와 수정 내역을 보존했다.
- 후보 누락·순위 실패·성공에서 각각 해시로 4개씩 뽑은 12개 사례를 같은 에이전트가 읽었다. 유용해 보이지만 미등록인 문서와 실제로 엉뚱한 문서가 모두 있었다. 일부 긴 본문은 발췌했다. 독립 관련성 판정이나 정답표 수정은 하지 않았다.

## 아직 하지 않은 일

1. 질문 목적에 맞게 관련 문서를 폭넓게 판정한 qrels 구축과 검수.
2. 실제 한국어 알람→관련 해결 기록 평가. 한국어 번역 질문이나 합성 기록으로 대체해 주장하지 않는다.
3. 질문 작성 당시 revision 복원 및 사후 해결 정보 유입 여부의 체계적인 검토.
4. 전체 코퍼스 청킹 검색, 실운영 메타데이터 필터, 실제 질의가 증상·환경을 보존하는지 검증.
5. 답변·해결 기록의 적용 가능성, 실제 복구 성공, 전체 API 지연·LLM 동시 상주 평가.

현재 로컬 search_rag는 LLM이 작성한 자연어 문자열로 상위 5개를 검색한다. 알람과 해결 기록이 같이 인덱싱되고 SearchRequest에 type/outcome 필터가 없다. 이것이 공개 질문 평가의 낮은 점수 원인이라고 연결해서 단정하지 않는다. 실제 운영에서 어떤 질의를 보내는지는 별도 관찰이 필요하다.

## 다음 세션의 권장 순서

새 모델 실험이나 기존 최종 점수 변경부터 시작하지 않는다.

1. **검색의 목적과 라벨 기준을 먼저 고정한다.** 주제 유사성, 같은 문제를 이해하는 데 직접 도움이 되는 문서, 특정 환경에서 적용 가능한 해결 기록을 구분한다. 최소한 직접 관련 / 부분 관련 / 무관과 불확실·판정 불가를 남긴다. 답변을 읽지 않은 상태에서 “해결 가능”이라고 판정하지 않는다.
2. **검수 대상을 결과를 보기 전에 정한다.** 실패만 고르지 말고 성공·출처·문제 유형을 포함한 표본을 고정한다. 기존 v4 12개는 진단에 이미 사용했으므로 새 독립 검수 표본이라고 부르지 않는다.
3. **검색 결과를 모아 판정한다.** 기존 정답과 MiniLM·BM25·Qwen·리랭커의 상위 결과를 합치고 중복을 제거한다. 모델명·점수·원래 정답 여부를 가리고 문서 순서를 섞는다. 어떤 후보까지 검토했는지 기록한다. 검색되지 않은 관련 문서 누락까지 해결되는 절차는 아니다.
4. **관련성 근거와 이견을 기록한다.** 질문의 목적·증상·환경과 문서 내용에 근거한 설명을 남기고, 무관한 단어 일치·조건 불일치·사후 정보 등을 구분한다. 독립 AI 검수는 사람의 정답 판정을 대체하지 않는다. 서브에이전트 사용은 재개 시 유효한 지침과 사용자 요청을 확인한다.
5. **기존 점수를 보존한 채 별도 라벨 버전으로 계산한다.** graded nDCG, 상위 결과의 관련성, 미판정 비율, 모델 간 이견을 함께 본다. 정답표 보강으로 오른 수치와 검색 방식 개선으로 오른 수치를 구분한다.
6. **운영에 맞는 별도 검증을 설계한다.** 공개 질문 시험은 스트레스 시험으로 유지하고 실제 알람·해결 기록 시험을 따로 둔다. 새 입력·모델을 선택하려면 개발 자료와 향후 독립 시험을 분리한다.

이 단계는 아직 실행하지 않았다. 문항 수·검수자·비용·판정 합의 방식도 다음에 정한다.
