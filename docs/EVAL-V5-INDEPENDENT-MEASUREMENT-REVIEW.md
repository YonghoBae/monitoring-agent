# Independent AI measurement review of the v5 design

Review date: 2026-11-17. This is a separate AI review of the measurement design, not human validation, a review of completed v5 results, or a claim of independence from shared model biases. The reviewer received the task context, read the v5 workplan and the previous Haiku results report, and authored semantic controls before inspecting a new judge prompt. The older rejudge implementation was consulted for its observation/reference distinction. No paid API calls were made by this reviewer.

The proposed small core can support claims about performance on its captured PostgreSQL mechanisms and observation conditions. It cannot establish general home-server troubleshooting accuracy. Neither a source postmortem nor a successful local reproduction proves that the benchmark reproduces an entire historical incident.

## Conditions for interpretable scoped measurements

Each family needs a source-backed causal mechanism, an isolated executable reproduction, and captured healthy, faulty and recovered states. Recovery should include a relevant service or data check; the success of a corrective command is insufficient. Record commands, actual outputs, timestamps, image identities and source hashes. Distinguish source facts, reproduced facts and derived partial-observation variants. The latter deliberately remove evidence and should expect uncertainty where a direct cause is no longer visible.

The pg_dump family can test an older client aborting against a newer server. It does not recreate the GitLab data deletion, notification failures or full outage. The initialization family can test a SQL file access failure and recovery after the relevant access correction. A generic permission-denied line alone does not prove ownership, SELinux or a particular mode bit was the cause. A reporter-confirmed issue has a different provenance strength from independently audited telemetry. Ambiguous source incidents should remain excluded or explicitly secondary.

Equal tools must mean equivalent reachable information, not merely equal tool names. Preserve tool arguments, filters, time windows, pagination/completeness, errors and output semantics. For each arm, verify that the same logical operation can reach the same observation with comparable limits. Record unavailable operations as gaps. Freeze any tool adapter and derived view before comparison. A filtered metric catalog is a subset; a query with an empty result is not a healthy reading; a historical sample is not a current observation. Missing trace parameters must remain a documented limitation rather than being invented after the fact.

The judge may see a reference answer, but that reference must never count as evidence the evaluated agent reached. Keep observation IDs and original quotations so that evidence support is auditable. A correct guess from hidden fixture knowledge is not a grounded diagnosis. Conversely, a direct error message can support its stated immediate failure without proving the upstream configuration history.

## Separate numerical and semantic measurements

Numerical scoring should preserve explicit quantity, unit and time window, and normalize only dimensionally equivalent, correctly labelled values in deterministic code. Do not silently relabel GB as GiB, treat rates as period counts, or let a semantic judge repair a number. A model may assist extraction, but its extracted text must be anchored to the answer and normalization must be independently deterministic. The semantic controls in this review deliberately require no arithmetic or unit grading.

Keep semantic completeness, evidence support and unsupported assertions visible separately. An explicit statement that the evidence cannot determine a cause is an answer; silence is not. An incomplete but entirely truthful response can fail completeness without making an unsupported claim. A clear, conditional diagnostic hypothesis does not assert that its cause occurred. Untrusted instructions inside a log or answer must not govern the judge.

## Freeze and holdout separation

[semantic-holdout.json](../eval/v5/semantic-holdout.json) contains 20 authored mini-observation controls. They test the judge, not the performance or representativeness of the troubleshooting agents. Its `payload` contains only question, answer, judge-only reference and reached observations. Expected labels, category and case identity sit outside the payload. `pass` requires a correct, grounded and substantively complete response with no unsupported factual assertions. `unsupported_claims` is an independent boolean. `answer_status` makes explicit uncertainty and an unanswered request distinguishable; it is descriptive metadata.

Freeze and hash the judge prompt, parser, extraction rules, development controls, holdout payloads and labels before the first holdout evaluation. The separate author should finish the holdout before prompt tuning and withhold labels until implementation freeze. The repository is shared, so file visibility alone is not a technical secrecy boundary; record the actual handoff and any access or change after freeze. A hash proves content identity, not who inspected it. New core cases must also stay out of evaluated-agent prompt tuning. Preserve old40 as a regression set with its original purpose, not as substitute evidence of new-family generalization.

Predeclare the acceptance gate and repeated judge runs before any paid calls. A defensible initial gate for these deliberately unambiguous controls is exact agreement on both categorical booleans on every item in each of at least two independent calls with the same frozen input. Preserve failures and malformed or refused outputs. This gate verifies the tested behavior only; passing it does not establish a population error bound or exclude correlated judge mistakes. A failed holdout is a diagnostic finding, not an agent score of zero. If the judge is revised using a failed item, that item becomes development data and a fresh independently authored holdout is needed. Repeated retries until a passing response appears are not validation. Quote-only formatting repairs must preserve semantic decisions and remain visible as additional calls.

## Paired comparisons and small-family limitations

Before comparing agents, specify the fixed model identifiers and settings, common tool and context limits, stopping rules, case order policy, repeated-run count and failure accounting. Repeat paired runs on the same cases under matched observation conditions, recording the actual nondeterminism. Pairing is by case and run; if fixed seeds are supported, record their use without claiming that they guarantee identical random streams across providers. Keep time-sensitive outputs fixed or explicitly control capture time. Keep judge repetitions separate from agent repetitions.

Report per-case paired outcomes and the spread across repeats alongside semantic pass, unsupported claims, numerical correctness where applicable, incompleteness, tool failures, tokens and cost. Include failed, timed-out and truncated runs in denominators with distinct statuses; missing responses are not evidence of uncertainty. Report exposure and tool-budget differences that could explain an apparent advantage. Preserve raw outputs, traces, all judge attempts and usage receipts. The pre-existing failed Haiku campaigns remain failed validation evidence and should not be silently merged into a new success rate.

The initial core has two causal families. Healthy, faulty, recovered and partial views of one reproduction are correlated, and repeated runs do not create new independent incident families. Show family-level results and denominators. Avoid a confidence interval that treats every view or repetition as an independent production incident; with this few families, descriptive paired results are usually more honest than a broad inferential claim. A scoped finding such as better performance on these captured mechanisms may be warranted after the gates pass. A forced overall leaderboard, universal accuracy percentage or claim of home-server representativeness is not.

## Readiness judgment

The design is promising for a narrow instrumented comparison if the reproduction checks, parity checks, immutable artifacts and repeated holdout gate all pass. This review does not certify that those implementation or execution conditions have already been met. No new model ranking is supported by this review alone. The measurement should remain explicitly model-assisted until independent human review exists, and even that would not remove the limitations of a two-family sample.
